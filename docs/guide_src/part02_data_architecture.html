Why LEFT JOIN? A normal join would drop the 775 orders that have no item rows. A LEFT JOIN keeps every order and fills missing parts with 0. Rule 8 of our project: never silently drop rows. 4. The architecture: how everything fits together

4.1 Which technology does what, and why we chose it

ToolIts job hereWhy this choice (and what we did not choose)
Python 3.11Producer, API client, validation rules, loaders, scripts, tests, dashboard code.Readable for beginners; huge ecosystem (pandas, kafka-python, psycopg2, Streamlit).
Apache Kafka 4.1Durable message conveyor between the producer and Spark. Remembers messages (offsets) so a restarted consumer can continue.It is the standard tool for streaming data and the one the professor expects. It decouples fast producers from slower consumers.
Spark 4.2 Structured StreamingReads Kafka in micro-batches, validates, removes in-batch duplicates, writes Parquet and PostgreSQL.Handles growth (the same code could run on a cluster) and gives checkpoints for recovery. Runs in Docker because on Windows it needs winutils.exe (an untrusted third-party download we refused).
ParquetLanding layer: every valid message Spark consumed, kept for audit and replay.Compact, columnar, typed. Simple files, no server.
PostgreSQL 16The warehouse: one clean row per order, plus reference tables and analytics views.Free, reliable, great SQL. INSERT ... ON CONFLICT gives the safe upsert.
Frankfurter APIReal external data: historical BRL→USD exchange rates.No key, no quota, official ECB rates, one request covers the whole period. (Weather API needs thousands of calls; a state-name API adds little.)
Airflow 2.10Runs the repeatable steps in order, with retries and logs.The standard orchestrator. Used only for finite tasks: an endless stream is not a task.
StreamlitThe dashboard.A dashboard in pure Python, no web-development skills needed.
Docker ComposeStarts Kafka, PostgreSQL, Spark and Airflow the same way on any machine.Reproducible setup, nothing to install by hand.

Why two Kafka addresses? Inside a container, "localhost" means the container itself. So Kafka advertises two doors: localhost:9092 for programs on your PC (the producer) and kafka:29092 for other containers (Spark, Airflow). This is configured in docker-compose.yml.
