15. Reconciliation: proving the numbers add up

15.1 The idea

Reconciliation means "count the same thing at every stage and explain every difference". Anyone can print a count; a good engineer shows that nothing was lost or invented. scripts/reconcile.py works from the source: it recomputes what each stage should contain using the same rules, then compares with what is actually there. It exits with code 1 if a difference is unexplained. It never adjusts an expected number to make a row pass.

15.2 Three sections

  1. Run level: each producer run versus the part of the file it covered (read, valid, rejected, published, dead-letter lines).
  2. Source level: unique records over the union of all runs. Runs overlap, so run totals cannot simply be added.
  3. Pipeline stages: Kafka → Spark → Parquet → PostgreSQL.

That file is the production state at the time of Phase 6. The final run (docs/evidence/10_automated_tests/final_reconcile_production.txt) covers six runs, after the re-ingestion and two Airflow runs, and ends with the same result line. The arithmetic of the first version:

Reading the pipeline arithmetic 99,725 messages in Kafka − 99 repeats removed inside one batch − 0 invalid = 99,626 rows in Parquet. Distinct record_uid in Parquet = 99,427; the other 199 Parquet rows are repeats that arrived in a later batch. PostgreSQL keeps one row per record_uid = 99,427. Every number is explained.

15.4 The "14 versus 15" story

An early reconciliation said "15 rejected orders" while the correct figure from the source was 14. I did not change the expected number. I investigated (scripts/explain_rejected_count.py): the extra one was one record_uid (92fc65a4...) that two overlapping runs had both rejected, so it appeared as two dead-letter lines. The fix was to separate counting levels: run-level (lines) and source-level (distinct record_uid). Evidence: docs/evidence/07_postgresql/rejected_14_vs_15_explained.txt.

Why the tool itself is trustworthy A separate test deliberately creates a mismatch and checks that reconcile.py returns exit code 1 (reconciliation_mismatch_exit_code.txt). A checker that can never fail proves nothing.
